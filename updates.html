Released

First release 2 Sep 2026

  • Paste a link, get one that can be read. The reader fetches the page on a server and returns plain HTML with no JavaScript in it at all, so anything that reads pages — including a model that would otherwise get an empty shell — sees the contents.
  • Structured data is the point. An Apple Music album page renders entirely in JavaScript, but it ships a schema.org MusicAlbum block with every track name, duration and link. readline reads that, so a shared album link comes back as all twenty-one titles rather than a login prompt. Recipes give ingredients and method, products give price and rating, feeds give their entries, question pages give their answers.
  • Nothing is stored. The reader link carries the original address inside it, so there is no database, no id to expire, and no link that outlives what it points at. Repeat reads are served from the edge cache for ten minutes.
  • Markdown and JSON as well as HTML. Add ?__format=md or ?__format=json to any reader link. Our own options are namespaced with a double underscore so they cannot collide with the target's own query string.
  • The fetcher will not touch a private address. Every spelling of one — 127.0.0.1, 2130706433, 0x7f000001, [::ffff:7f00:1] — collapses to the same integer and is refused, and every redirect hop is checked again rather than followed blind.
  • A kill switch in config.js, which is neither bundled nor fingerprinted, so the page can be taken out of service from GitHub's web UI without a deploy. Links already shared are served by the worker, so stopping those means stopping it.

Built because an AI cannot open an Apple Music link, and the album was worth talking about.

Next

Roughly in order. Nothing here is promised.

  1. Sites that need a real browser

    A few pages have nothing in their HTML and no structured data either — the text only exists after their JavaScript runs. Rendering those needs a headless browser, which is a much larger thing than this, and would be the first part of readline that costs money.

  2. PDFs

    Currently refused with a note saying so. Extracting text from one is self-contained work and probably the most useful thing missing.

  3. A bookmarklet

    The page already reads /?u=… on load, so this is a one-line link away — it just needs somewhere to live.

  4. Better answers for hostile sites

    X, Instagram and LinkedIn serve almost nothing to a fetcher. Where a public API exists, using it would beat the note that currently explains the emptiness.
